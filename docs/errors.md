# OpenAI 兼容 API 错误排查

先记录完整的 HTTP 状态码、响应 JSON、请求模型名和 Base URL。不要只看客户端显示的“连接失败”。

## 401 Unauthorized

常见原因：

- Key 为空、过期或属于另一个端点；
- `Authorization: Bearer ...` 被客户端配置覆盖；
- 代理或网关没有转发 Authorization；
- Key 前后有空格或被错误转义。

先用最小请求验证，不要马上更换多个变量。

## 402 Payment Required

常见原因：

- 按量余额不足；
- 日卡/周卡的订阅额度已经耗尽；
- 套餐支持的分组与当前模型不匹配；
- 额度用尽后继续使用钱包余额的开关没有打开。

不要把 402 当成网络超时反复重试。先确认账户余额、订阅剩余额度、有效期和扣费开关。

## 404 Not Found

优先检查：

- Base URL 是否已经包含 `/v1`，代码是否又拼接了一次；
- 使用的是 `/chat/completions` 还是端点实际支持的路径；
- 模型 ID 是否来自当前模型列表；
- 客户端是否把模型别名改写成了不存在的名称。

## 429 Too Many Requests

记录：并发数、重试次数、每次重试间隔、响应头中的限流提示（如果有）。

重试要使用指数退避，并给同一业务任务保留稳定的 `task_id`。否则超时或重复提交时，可能无法区分限流重试和重复计费。

## 返回成功但内容为空

核对：

- `choices` 是否存在；
- `finish_reason` 是否为 `length`、`tool_calls` 或其他非 `stop` 状态；
- 流式响应是否被客户端提前关闭；
- `model` 和协议路径是否符合客户端预期。

## 最小证据包

排错时保留以下字段即可，不要上传 Key 或完整用户提示词：

```text
时间
HTTP status
endpoint（隐藏域名外的敏感信息）
model
request_id（如果有）
usage
finish_reason
重试次数和间隔
```
