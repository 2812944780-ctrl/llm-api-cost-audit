# FAQ

## 这个项目是 SDK 吗？

不是。它是一个轻量的 usage 记录与成本审计工具，兼容使用 OpenAI 风格响应的接口。你可以把它接到现有 SDK 或自己的 HTTP 客户端旁边。

## 必须使用某个特定接口吗？

不需要。默认示例使用通用占位配置，任何兼容的 `base_url` 都可以替换。仓库另提供 [深空 API 接入指南](using-deep-space-api.md) 作为一个可选的实际回归入口。

## GitHub 用户怎么领 2 元额度？

在 [深空 API](https://api.91kun.top) 注册后，加入售后 QQ 群 **1041569325**，入群申请填写 `GitHub + 站内用户ID或昵称`，然后申请领取 **2 元站内 API 使用额度**。**每个用户限领一次**，不是注册自动到账。请勿提供 API Key 或密码。完整步骤见 [深空 API 接入指南](using-deep-space-api.md)。

## 为什么入群申请需要写 GitHub？

用于识别本次活动来源；站内用户 ID 或昵称用于对应你的站内账号。只写 ID 无法判断来源。不要在公开 GitHub Issue 中提交这些领取信息，请通过售后群申请。

## 为什么日志里要保存 `task_id`？

为了识别短时间内同一业务任务的重复请求。超时后服务端可能已经生成了一部分 Token，无条件重试会制造重复用量。

## `usage` 缺失怎么办？

先确认端点和客户端是否支持 usage 返回，再检查流式请求的结束事件。没有 usage 时，不要把字符数当成 Token 数，也不要把估算值写成实际账单。

## 报告返回码为 1 是错误吗？

当检测到 HIGH 级别的重复调用时，报告返回 1，方便 CI 阻止问题进入生产。查看 JSON 报告和重复任务明细即可。

## 缓存价格能直接当作最终成本吗？

不能。缓存是否命中取决于请求前缀、上下文、时间间隔和服务端策略。请记录实际 usage 与账单，不要假设固定命中率。

## 日志可以提交到 GitHub 吗？

不要提交真实日志。日志可能包含用户提示词、任务 ID、模型名和业务时间。使用仓库内置的样例日志或先脱敏。

## 如何报告问题？

提供脱敏后的状态码、请求路径、模型名、usage 字段形状、finish_reason 和复现步骤。不要提供 Key、Cookie、完整提示词或真实账单。
