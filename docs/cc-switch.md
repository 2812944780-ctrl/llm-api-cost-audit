# CC Switch 配置核对

CC Switch、Claude Code、Codex 等工具切换供应商后，最容易误判的是“界面已经切换”而请求仍然走旧配置。

## 配置前记录

```text
当前工具
目标 Base URL
目标模型 ID
配置文件位置
是否使用环境变量
```

API Key 只放在本机安全配置或环境变量，不要提交到仓库。

## 切换后的最小回归

先完全退出正在运行的 CLI 进程，再重新启动。只发一条短请求，并检查：

- 响应里的 `model`；
- `usage` 是否返回；
- `finish_reason`；
- 服务端用量明细中的时间和请求 ID；
- 客户端日志里的实际请求地址（隐藏 Key）。

只看 CC Switch 的供应商名称不够，它可能只是本地配置标签。

## 常见问题

### 仍然走旧模型

检查旧的环境变量、工具级配置和系统级配置是否同时存在。关闭旧进程后再启动，避免进程继续持有旧环境。

### 401

检查当前配置中的 Key 是否属于当前 Base URL，以及 Authorization 是否被多层配置覆盖。

### 404

检查模型 ID和路径拼接。不同工具对 Base URL 是否包含 `/v1` 的约定可能不同，最终以实际请求 URL 为准。

### 429

先降低并发和自动重试次数，记录每次重试的时间。不要用不断重试来判断“切换是否成功”。

### 账单对不上

把客户端记录的 `model`、`usage`、时间和请求 ID与服务端明细对照。缓存命中和未命中不要用固定比例推算，只使用实际观察值。
